# Load-test handover — 2026-10-02

Everything needed to resume the load-testing effort on another machine. The load test lives on the
**`loadtest`** branch (never merged to `main`); artifacts here are on that branch.

## Bottom line (what we learned)
- **The app is Fabric-bound, not app-bound.** At 100 concurrent users the VM CPU peaked at only **~20%**
  — *with the Locust generator running on the same VM* — so the app host has ~80% headroom. Latency climbs
  because connections sit **waiting on Fabric query responses**, not computing.
- **Throughput ceiling ≈ 6–7 RPS** on the current F8, set by Fabric.
- **Connection-pool knee ≈ 20.** `FABRIC_POOL_MAX=10` starves it (throughput halves); `20` is the sweet
  spot; `30`/`40` give no gain and worse tails. **Keep `FABRIC_POOL_MAX=20`.**
- **Latency vs users** (pool 20): 20u → p50 1.6 s; 40u → p50 3.1 s; 100u → p50 9.5 s (roster p50 15 s).
  Usable interactive latency holds to ~20 concurrent on this setup; past that it degrades but **does not
  error out** (only 1–3 transient `RemoteDisconnected` keep-alive races per run).
- **Levers that help:** bigger Fabric SKU (more CU) and/or cheaper heavy reads (roster + analyst-scoped
  cohort are the hogs; lean on `refCache`/`groupCache`/`identityCache`). **Won't help:** more app CPU/RAM,
  more replicas, bigger pool — all downstream of the Fabric wall.
- **Caveat:** the Locust mix weights analysts heavily (widest, most expensive queries). Real
  teacher-dominated traffic is lighter per request, so true usable concurrency is likely higher.

## How to run it (single box, which is how we ran it)
Full steps: [RUNBOOK-this-device.md](RUNBOOK-this-device.md). Condensed:

1. **Image** on the box: `assessment-webapp:0.7.1-loadtest` (built from this branch; `package.json` is
   0.7.0 — the `.1` is just the image tag). Tar + checksum workflow in the runbook.
2. **App container** (`awlt`) via rootless Podman in WSL as `appuser` — wrap every podman cmd with
   `wsl -u appuser bash -c "export XDG_RUNTIME_DIR=/run/user/1001 && <cmd>"`:
   ```
   podman run -d --name awlt --restart=unless-stopped --env-file /mnt/c/temp/load_test/.env.loadtest -p 0.0.0.0:3001:3000 localhost/assessment-webapp:0.7.1-loadtest
   ```
   Env changes need a **stop+rm+run** (podman only reads `--env-file` at `run`).
3. **Generator**: Locust runs **inside the same WSL VM** (installed in a `virtualenv` — `~/locustenv` —
   because the distro is PEP-668 externally-managed; `pip install --user` collides with system `zope`).
   `python -m locust -f /mnt/c/temp/load_test/locustfile.py --host http://127.0.0.1:3001`, UI at
   `http://localhost:8089`.

## Gotchas we hit (so the next run is smooth)
- **`LOADTEST_USERS` has DIFFERENT formats on each side.** Locust wants `upn:role` (it parses the role for
  weighting); the **app container wants BARE UPNs** — `allowedLoadtestUsers()` in `webapp/src/lib/loadtest.ts`
  does **not** strip the `:role` suffix, so `:role` in the container's env makes the allow-list never match
  the bare UPN Locust sends → **403 on every page** (seed still 200s via `DEV_FAKE_UPN` fallback, which
  masks it). **KNOWN BUG to fix:** make `allowedLoadtestUsers()` strip `:role` so one string works on both
  sides.
- **`LOADTEST_ALLOWED_CIDRS` must be blank** for the WSL/pasta path — the app sees a non-loopback client IP,
  so a `127.0.0.1/32` allow-list 403s all matched routes (middleware CIDR check). Blank = allow (key is the
  real gate).
- **`/api/loadtest/seed` ≈ 16 s is NOT a user metric** — it serially runs ~7 Fabric queries (windows + up to
  5 group lookups + full cohort) for the analyst identity. No live page does that; exclude it from headline
  numbers. It's cached per-UPN in the locustfile, so it barely appears in multi-user runs.
- **Windows loopback reaches the container.** On the box, `curl http://127.0.0.1:3001` works (wslrelay
  forwards the rootless-published port to the Windows host, same as IIS→`aw`:3000). Running the generator
  on another machine needs `0.0.0.0` publish + Windows firewall + likely `netsh portproxy` — we avoided all
  that by running Locust inside the WSL VM.
- Container-only box: no `node`, no `gh`, no `winget` (Windows Server). Build validates types; push via GCM.
