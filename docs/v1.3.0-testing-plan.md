# v1.3.0 — Testing Plan

Acceptance tests for everything added or changed in v1.3.0. Run top-to-bottom on **dev** first; promote to
**live** only after dev passes. Test as each **role** noted (Teacher, School Administrator, Specialist
Teacher, Regional Analyst) — scope differences are the whole point of several features.

v1.3.0 themes: **(1)** writing traits in COIL order, **(2)** the Reports rebuild (oversight roll-up trees +
TCRCE + language filter), **(3)** backend durability fixes (IPP/adaptation persistence, staff email
reconciliation). Grace-period wording was also removed.

---

> **Deploy-live coupling:** the stricter `usp_MergeStaff` write rule and the `StaffRoleOverride` table go
> live together (both are in the bundle). **Before the first post-deploy ingest**, seed the overrides —
> every Instructional Coach and anyone who must count as an admin without a PS role — via
> `/admin/staff-roles` (or `usp_SetStaffRoleOverride`), or they are dropped on that ingest. Tech-Services
> maintenance staff do **not** go here — they only need the `CanMaintain` capability (`/admin/staff-access`).
>
> **Timing:** a **role override** is applied by the staff merge, so it takes effect on the next **ingest**
> (also when its PS-derived school scope is verified) — the Save screen prompts to confirm this. The
> **Maintenance capability** is read live from `StaffAppAccess`, so it is **effective immediately** (no
> ingest, no RLS) — IT maintenance-only staff who never appear in a PS export don't wait for anything.
